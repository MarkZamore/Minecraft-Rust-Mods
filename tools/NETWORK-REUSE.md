# Повторное использование сетевого мода

Проверка от 7 ноября 2026 года для Minecraft 26.3, Horizon
`6560641ba51a452f6bc2407baa4eb1b3be517ca8`, Windows x64.

## Вывод

Ближайший к требованиям проекта кандидат — авторский
[e4steam](https://github.com/Kamilhik/e4steam). Его готовые JAR предназначены
для Java Minecraft с Fabric/Quilt, Forge или NeoForge. Нативный Horizon
не загружает эти Java-моды, поэтому совпадение версии Minecraft 26.3
не подтверждает двоичную совместимость.

Авторский [README](https://github.com/Kamilhik/e4steam/blob/main/README.md)
заявляет для e4steam 0.3.4 версии 1.17–26.3 и Windows x64 как основную
платформу. Есть Steam-лобби, приглашения, авторизация и транспорт Valve.
[Матрица совместимости](https://github.com/Kamilhik/e4steam/blob/main/COMPATIBILITY.md)
отдельно отмечает непроверенные сценарии: наличие собранного JAR не означает
проверенное соединение двух аккаунтов на каждой версии.

## Аудит существующей реализации проекта

Существующий Rust-мост проверен на базе `9d6d980`.
[Исправление faa2506](https://github.com/MarkZamore/e4steam/commit/faa25063441b83f589caab505dfefda8932e4fe4)
устраняет два подтверждённых сбоя: блокирующее закрытие общего доступа
при заполненной очереди и отправку READY до регистрации одноразовой
Steam-идентичности гостя. Отмена публикации теперь также делает устаревшие
запросы недействительными. Публичный интерфейс и транспорт Valve сохранены.

Компонентные проверки: 10 тестов, без пропусков, Clippy и форматирование — PASS.
Реальные приглашения через оверлей, два Steam-аккаунта и измерение передачи
чанков — NOT RUN в этом аудите. Точный runtime каждой сборки проверяется
отдельно; успешные компонентные тесты не заменяют игровую приёмку.

## Варианты интеграции

| Вариант | Оценка для Horizon |
| --- | --- |
| Установить готовый e4steam JAR | Не подходит: нужен Java-загрузчик и его игровые классы. |
| Перенести необходимые части авторского e4steam | Реалистичный кандидат; приглашения, протокол и авторизацию нужно связать с жизненным циклом Horizon. Объём повторно используемого кода устанавливается по конкретному порту. |
| Запускать авторскую Java-часть отдельным помощником | Требует выделения независимого компонента, отдельного процесса и обмена с Horizon. Готовая автономная поставка для этого сценария не подтверждена. |
| Использовать Steamworks через Rust bindings | Уже используется текущим нативным мостом; сетевой транспорт предоставляет Valve. Интеграция с игрой остаётся кодом проекта. |

В [SteamRuntime.java](https://github.com/Kamilhik/e4steam/blob/main/common/src/main/java/link/e4steam/steam/SteamRuntime.java)
есть связи с `Agnos` и `E4steamClient`. Поэтому перенос целого класса
в отдельный процесс нельзя считать готовым решением без проверки зависимостей.

Нативный мост из `MarkZamore/e4steam/source/native` следует обозначать как
адаптацию проекта, использующую сторонние Steamworks bindings. Нельзя выдавать
его за готовый авторский JAR или утверждать, что автор проверял его с Horizon.

Авторская [лицензия Apache 2.0](https://github.com/Kamilhik/e4steam/blob/main/LICENSE)
допускает производные работы с сохранением обязательных уведомлений.
При фактическом переносе закрепить исходный commit, SHA-256, состав файлов,
зависимости и лицензии в lock и квитанции поставки.

## Приёмка перед заменой

Проверить точные Windows-клиенты хоста и гостя: публикацию мира и закрытие
меню, копируемый адрес и кнопки чата, приглашение и присоединение через
Shift+Tab, проверку Steam-идентичности, выход и повторное открытие мира,
сохранность настроек и нагрузку при передаче чанков. Сравнивать на одинаковых
условиях с текущим мостом. Сама замена транспорта не подтверждает исправление
прав команд или синхронизации Orbital Laser: это отдельные игровые механизмы.

Статус: анализ исходников и совместимости — PASS; установка авторского JAR
в Horizon, автономный Java-помощник и двухаккаунтное сравнение — NOT RUN.
Этот документ не разрешает публикацию непроверенной замены.
